# Tasks: an introduction

Tasks represent activities within a workstream which are sufficiently important to be worth capturing in a structured way. Tasks may be broken down into subtasks.

The ability to break things down in this way allows you to see - via the **Taskmap** and **Roadmap**- how tasks fit into the overall context. This breakdown provides content for the **Tasklist**, which gives way to a practical prioritisation of the tasks being worked on.

## Some deliberate constraints

Too much freedom can be a problem in workstream visualisation, leading to information overload.

Juralio helps with this by imposing two types of constraints on task numbers within a workstream.

* Workstreams can only have a maximum of **16 phases**
* There can be only **six levels of subtask** - from A (the highest) down to F
* Each task can have up to only **eight direct subtasks**
* Each workstream has a limit of **300 tasks**. If you reach this limit, split the work into separate workstreams for easier management.

If you bump up against these constraints, there is always a way of reorganising how you sub-divide your tasks.
